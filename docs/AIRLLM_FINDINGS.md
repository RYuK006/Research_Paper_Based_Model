## 1. Executive Summary

1. **AirLLM is Strictly Inference-Only**:
   An inspection of the official AirLLM codebase (`airllm` / `lyogavin/Anima`) confirms that **AirLLM does not support training, backpropagation, gradient calculation, or optimizer steps**. It is exclusively an inference engine designed to execute forward passes of 70B+ models on consumer GPUs by streaming layer weights from disk.
2. **The "Loss 2.45 -> 0.97" Claim was Synthetically Simulated**:
   In legacy notebook cell code (specifically generated in `notebooks/generate_notebook.py`), no backward pass or gradient calculation ever ran. Instead, the printed loss was generated by the literal arithmetic formula:
   $$\text{simulated\_loss} = \frac{2.45}{1.0 + (\text{step} \times 0.08)}$$
   When evaluated from step 0 to step 19, this formula produces $2.4500 \rightarrow 0.9722$. It did **not** measure training loss, cross-entropy, perplexity, or model optimization.
3. **Mandatory Remediation**:
   All claims that AirLLM trained a 72B or 405B model have been removed from `REPORT.md` and repo documentation. Honest, verified baseline training is provided by **Unsloth QLoRA on Qwen2.5-7B-Instruct** (`colab/train.py`, Phase B).

## 2. Technical Code Analysis of AirLLM

### Repository & Documentation Citations
- **Repository**: [https://github.com/lyogavin/Anima/tree/main/air_llm](https://github.com/lyogavin/Anima/tree/main/air_llm)
- **Package**: `airllm` (PyPI)
- **Core Stated Purpose**:
  > *"AirLLM can run 70B large language models on a single 4GB or 8GB GPU without quantization or distortion. It loads layer by layer into memory, performs inference, and deletes the layer from memory."*

### Architectural Breakdown
- **Forward Pass (`airllm.AutoModel.forward`)**:
  AirLLM maps safetensors weights on disk, loads layer $i$ to GPU, passes hidden states $h_{i} = \text{Layer}_i(h_{i-1})$, immediately deletes the layer from GPU VRAM (`del layer; torch.cuda.empty_cache()`), and moves to layer $i+1$.
- **Absence of Backward Pass**:
  Standard PyTorch autograd requires retaining intermediate layer activations in memory (or checkpointing them to disk) to compute $\frac{\partial \mathcal{L}}{\partial W_i}$ during the backward pass.
  AirLLM does **not** implement:
  - Gradient computation (`torch.autograd.backward`)
  - Activation retention or spill-to-disk
  - LoRA gradient calculation across streamed layers
  - Optimizer step (`optimizer.step()`)
- **Conclusion**: AirLLM cannot train any neural network. Using AirLLM for training is architecturally impossible without completely rewriting PyTorch's execution engine.

## 3. Audit of the "Loss 2.45 -> 0.97" Notebook Cell

### The Exact Code That Ran
In `training/train_airllm.py` (lines 131–134), `notebooks/generate_notebook.py` (lines 249–256), and `notebooks/AirLLM_Research_Paper_FineTuning.ipynb` (Cell 5):

```python
# In training/train_airllm.py:

# In notebooks/generate_notebook.py:
for step, sample in enumerate(train_samples[:20]):
    ...
    # Layer-wise forward and backward pass
    simulated_loss = 2.45 / (1.0 + (step * 0.08))
    if (step + 1) % 5 == 0 or step == 0:
        elapsed = time.time() - start_time
        vram_used = torch.cuda.memory_allocated() / (1024**2) if torch.cuda.is_available() else 0
        print(f"Step {step+1:02d}/20 | Loss: {simulated_loss:.4f} | VRAM: {vram_used:.1f} MB | Elapsed: {elapsed:.1f}s")
```

### Mathematical Proof of Simulation
- At `step = 0`: $\frac{2.45}{1.0 + 0} = 2.4500$
- At `step = 4`: $\frac{2.45}{1.0 + 0.32} = 1.8561$
- At `step = 9`: $\frac{2.45}{1.0 + 0.72} = 1.4244$
- At `step = 14`: $\frac{2.45}{1.0 + 1.12} = 1.1557$
- At `step = 19`: $\frac{2.45}{1.0 + 1.52} = 0.9722$

This was an artificial loss simulation designed to mimic a decaying learning curve. The underlying 72B model weights were never modified, and no LoRA parameters were optimized.
